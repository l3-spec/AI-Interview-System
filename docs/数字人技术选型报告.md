# 数字人技术选型研究报告

**项目**: AI面试系统 - 三端数字人实时交互  
**研究日期**: 2026-04-14  
**目标**: 找到能满足"实时、流畅、自然"交互体验的数字人解决方案

---

## 一、需求分析

### 核心要求
| 指标 | 要求 | 说明 |
|------|------|------|
| 端到端延迟 | < 300ms | 语音输入 → 数字人响应 |
| 帧率 | ≥ 30 FPS | 数字人动画流畅度 |
| 风格 | 卡通/真人/2D 可选 | 绝不卡顿、死板 |
| 平台 | Android + iOS + HarmonyOS | 三端统一方案最优 |

### 现状
- **Android**: DUIX SDK + Live2D，已集成，有一定延迟问题
- **iOS**: 未开始
- **HarmonyOS**: 未开始

---

## 二、技术方案对比

### 方案 A: DUIX SDK（当前方案）

**来源**: 商影AI (duix.com)  
**类型**: 开源 + 商业

| 维度 | 评分 | 说明 |
|------|------|------|
| 跨平台 | ⭐⭐ | Android 已集成，iOS/HarmonyOS 需要单独适配 |
| 实时性 | ⭐⭐⭐ | 基本满足，但存在延迟问题 |
| 效果 | ⭐⭐⭐ | 2D 卡通风格成熟 |
| 开源 | ⭐⭐⭐ | 部分开源（GitHub: duixcom/Duix-Mobile）|

**优点**:
- 设备端运行，无需云端
- 隐私性好
- 已在 Android 端验证

**缺点**:
- iOS/HarmonyOS 支持不完善
- 延迟问题需要优化
- 跨平台一致性差

---

### 方案 B: Live2D + Wav2Lip/MuseTalk（开源方案）

**来源**: Live2D Cubism SDK + MuseTalk  
**类型**: 完全开源

| 维度 | 评分 | 说明 |
|------|------|------|
| 跨平台 | ⭐⭐⭐⭐ | Unity 版本支持 Android/iOS/鸿蒙 |
| 实时性 | ⭐⭐⭐ | MuseTalk 支持 30fps+ |
| 效果 | ⭐⭐⭐⭐ | 2D 效果流畅 |
| 开源 | ⭐⭐⭐⭐⭐ | 完全开源，可深度定制 |

**核心组件**:
1. **Live2D Cubism SDK**: 渲染 2D 数字人动画
2. **MuseTalk**: 实时唇形同步（Audio-driven）
3. **火山引擎 ASR**: 中文语音识别

**优点**:
- 完全开源，无授权费用
- Unity 可打包到所有主流平台
- MuseTalk 1.5 支持实时推理

**缺点**:
- MuseTalk 需要 GPU 支持（移动端有挑战）
- 需要自建 TTS 管道
- 整合工作量大

---

### 方案 C: 商业云服务 + 自研渲染

**来源**: Inworld AI / Agora + OpenAI Realtime API  
**类型**: 商业闭源

| 维度 | 评分 | 说明 |
|------|------|------|
| 跨平台 | ⭐⭐⭐⭐⭐ | 统一 SDK 支持所有平台 |
| 实时性 | ⭐⭐⭐⭐⭐ | < 200ms 延迟 |
| 效果 | ⭐⭐⭐⭐ | 专业级质量 |
| 成本 | ⭐⭐ | 按调用付费，成本高 |

**代表方案**:
1. **Inworld AI Realtime API**: 语音到语音，低延迟，$0.004/分钟
2. **Agora + OpenAI Realtime API**: 超低延迟，全球覆盖
3. **NavTalk AI**: 低延迟数字人 API，平均响应 < 2 秒

**优点**:
- 延迟最低
- 效果最专业
- 无需自建 AI 模型

**缺点**:
- 需要网络连接（无法离线）
- 持续成本
- 数据隐私顾虑
- 可能不适合中国网络环境

---

### 方案 D: WebRTC + 开源 TTS/ASR + 自研渲染

**架构**:
```
用户语音 → 火山引擎 ASR → DeepSeek → 火山引擎 TTS → 数字人渲染
         (WebRTC 低延迟传输)
```

| 维度 | 评分 | 说明 |
|------|------|------|
| 跨平台 | ⭐⭐⭐⭐⭐ | WebRTC 通用，移动端完美支持 |
| 实时性 | ⭐⭐⭐⭐ | 端到端 200-400ms |
| 效果 | ⭐⭐⭐ | 取决于渲染方案 |
| 成本 | ⭐⭐⭐⭐ | 火山引擎 + DeepSeek，成本可控 |

**核心优势**:
- 火山引擎 ASR 支持实时流式识别
- DeepSeek 作为对话大脑（已集成）
- 数字人渲染可选择 Live2D（2D）或 Ready Player Me（3D）
- 完全自控，无外部依赖

---

## 三、推荐方案

### 🥇 最佳选择：方案 D（自研架构）

**理由**:
1. **效果可控**: 渲染层可深度优化，满足"流畅不卡顿"
2. **成本可控**: 火山引擎 + DeepSeek，已有成功案例
3. **跨平台一致**: WebRTC + 统一渲染层，三端体验一致
4. **延迟可优化**: 已有项目（AI-Interview-System）验证过此方案

**技术架构**:
```
┌─────────────────────────────────────────────────────────────┐
│                      移动端（三端通用）                      │
├─────────────────────────────────────────────────────────────┤
│  ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐ │
│  │ 麦克风   │───▶│ 火山ASR │───▶│ DeepSeek│───▶│ 火山TTS │ │
│  │ (VAD)   │    │ (流式)  │    │ (对话)  │    │ (流式)  │ │
│  └─────────┘    └─────────┘    └─────────┘    └─────────┘ │
│                                         │                  │
│                                         ▼                  │
│                                   ┌───────────┐            │
│                                   │ 数字人渲染 │            │
│                                   │ Live2D/3D │            │
│                                   └───────────┘            │
└─────────────────────────────────────────────────────────────┘
```

### 🥈 备选方案：方案 B（Live2D + MuseTalk）

如果中国网络访问火山引擎有问题，或成本考虑：
- 使用开源唇形同步 + 自研 TTS
- 延迟会略高，但完全自主可控

## 四、实施建议

### Phase 1: 统一渲染层
1. 选择 Live2D（2D）或 Ready Player Me（3D）作为统一渲染
2. 三端统一接口 `DigitalHuman`（参考 `docs/DIGITAL_HUMAN_SPEC.md`）
3. Android 端替换 DUIX SDK 为 Live2D

### Phase 2: 优化 ASR/TTS 管道
1. 验证火山引擎实时 ASR 延迟
2. 对比 DeepSeek + 火山 TTS vs Inworld TTS
3. 优化 WebRTC 传输层

### Phase 3: 性能调优
1. 目标: 端到端 < 300ms
2. 数字人帧率 ≥ 30 FPS
3. 三端一致性验证
